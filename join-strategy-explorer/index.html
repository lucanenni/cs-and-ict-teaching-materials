Come funziona?

  • • Il nested loop join è il metodo più semplice: per ogni riga della prima tabella, scorre tutte le righe della seconda cercando una corrispondenza. Il numero di confronti cresce come N × M — con tabelle grandi diventa rapidamente enorme.
  • • L'hash join costruisce prima una struttura hash su una delle due tabelle (una passata, O(M) inserimenti), poi scansiona l'altra tabella una sola volta facendo per ogni riga un lookup in tempo costante — O(N) lookup in totale. Il totale cresce come N + M, molto più lentamente di N × M.
  • • Un query planner scelge quale strategia usare in base alle dimensioni delle tabelle e agli indici disponibili: per tabelle grandi senza un indice sulla chiave di join, l'hash join è quasi sempre più veloce.

Costruire la hash table ha un costo fisso, anche se piccolo (qui M operazioni), più la memoria per tenerla in RAM. Su tabelle davvero piccolissime (poche righe), N × M può essere comunque minore o comparabile a N + M più questo costo di costruzione, e il nested loop risulta più semplice ed efficiente senza nemmeno dover allocare una struttura aggiuntiva. Inoltre, se esiste già un indice sulla chiave di join di una delle due tabelle, un "nested loop con indice" può essere competitivo anche su tabelle più grandi, perché ogni ricerca nell'indice è quasi quanto un lookup hash. Per questo i query planner valutano i costi stimati di più strategie prima di scegliere, invece di usarne sempre una sola.
