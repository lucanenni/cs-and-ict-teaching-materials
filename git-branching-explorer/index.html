Come funziona?

  • • Ogni commit punta al proprio commit padre (o a due, se è un merge): insieme formano un grafo, non una semplice lista.
  • • Un branch non è altro che un'etichetta che punta a un commit — quando fai un nuovo commit, l'etichetta del branch attuale si sposta in avanti da sola.
  • • HEAD indica su quale branch ti trovi in questo momento: è quel branch che si aggiorna quando fai un commit.

Se il branch che stai unendo è semplicemente "più avanti" del tuo (cioè il tuo commit attuale è un antenato diretto del suo), Git non ha bisogno di creare un vero commit di merge: sposta semplicemente l'etichetta del tuo branch in avanti fino a raggiungere l'altro. Questo si chiama fast-forward. Se invece i due branch si sono sviluppati in parallelo con commit diversi, serve un vero commit di merge, con due genitori, che unisce le due storie. Prova entrambi i casi in questa pagina: fai un merge subito dopo aver creato un branch (senza nuovi commit su nessuno dei due) per vedere il fast-forward, oppure fai commit su entrambi i branch prima di unirli.
