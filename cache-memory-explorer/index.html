Memoria cache

La RAM è troppo lenta per stare al passo con la CPU: la cache è una memoria piccola ma velocissima che tiene una copia dei dati usati di recente. Funziona solo perché i programmi tendono a riusare indirizzi vicini — la località

Come funziona?

  • • Ogni indirizzo appartiene a un blocco di 4 indirizzi consecutivi, e ogni blocco ha un'unica linea di cache assegnata (indice = indirizzo del blocco modulo 8): è la cache "a mappatura diretta".
  • • Se il blocco richiesto è già in quella linea (stesso tag), è un hit: velocissimo. Altrimenti è un miss: bisogna andare in RAM, caricare l'intero blocco in cache (anche se serviva un solo indirizzo) e solo allora rispondere.
  • • Caricare un blocco intero, non un solo indirizzo, è una scommessa: se il programma continuerà a leggere indirizzi vicini (buona località), quel blocco servirà altre volte gratis. Se salta a caso, la scommessa è persa — ed è esattamente quello che mostra il pattern "sparsa" qui sopra.

Nel pattern "in conflitto", gli indirizzi 0 e 32 puntano a blocchi diversi che però condividono la stessa linea di cache (0 ÷ 4 = 0, 0 mod 8 = 0; 32 ÷ 4 = 8, 8 mod 8 = 0). Accedendo alternativamente a 0 e 32, ogni accesso sfratta il blocco caricato dall'accesso precedente: pur riusando ripetutamente solo due indirizzi — in teoria il caso ideale per una cache — l'hit rate è 0%. Si chiama miss di conflitto (a differenza dei "miss di capacità", dovuti a una cache troppo piccola per l'intero programma, o dei "miss a freddo", il primo accesso a un dato mai visto prima). Le cache reali riducono questo problema con l'associatività (più linee possibili per ogni blocco, non una sola), al prezzo di un circuito di ricerca più complesso.
