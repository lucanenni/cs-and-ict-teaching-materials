Come funziona?

    Dipende. Le sessioni danno al server il controllo totale e immediato: basta cancellare una riga dalla tabella per invalidare un accesso all'istante — ottimo per sicurezza e per un logout che funziona davvero subito. Il costo è che il server deve mantenere quella tabella, il che diventa scomodo quando le richieste sono distribuite su tanti server diversi (serve condividerla, es. con un database centrale). I token firmati non richiedono nessuna tabella: qualunque server con la stessa chiave segreta può verificarli da solo, il che li rende comodi per sistemi distribuiti — ma proprio per questo, invalidare un singolo token prima della sua scadenza naturale è difficile (serve comunque una qualche forma di "lista nera", che riporta il problema da cui si voleva scappare). Sistemi reali spesso usano token a vita breve, rinnovati periodicamente, come compromesso.
